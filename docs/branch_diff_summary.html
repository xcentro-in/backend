PO-Invoice Matching Engine — Decision Flow
RunMatchingForInvoice
1
Idempotency check
Skip if match_status ≠ PENDING_MATCH
2
PO number check
No PO number → ORPHAN_INVOICE immediately
3
PO lookup (Redis cache → DB)
5-min TTL, key: po_cache:<bid>:<po_num>
4
Amount check
invoice.net_amount ≤ po.remaining_balance ± 1%
5
Line-item matching
Phase 1: SKU exact match → Phase 2: description Dice coeff ≥ 0.5
6
Apply result
MATCHED: update PO balance, qty_received, invalidate cache
MISMATCH: flag for procurement review + write audit

Match Status States

✓ MATCHED
PO found, amounts within 1%, all line items matched by SKU or description similarity. PO balance decremented; PO transitions OPEN → PARTIALLY_INVOICED → CLOSED.
⚠ MISMATCH
PO found but amount exceeds balance OR line items have qty/price variance. Flagged for Procurement Manager review. Full details stored in match_details JSONB.
◎ ORPHAN_INVOICE
No matching PO found in the business. Stored as orphan — re-matched automatically when a PO with the same po_number is validated later.
