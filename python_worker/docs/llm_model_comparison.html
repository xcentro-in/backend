invoice2data Template Hybrid — Is It Worth It?

The current system uses invoice2data regex templates as a first-pass extraction layer, with LLM as fallback. Here's when that helps and when it doesn't.

✅ Where the hybrid adds real value

Speed: Template extraction completes in ~200ms vs 5–12s for an LLM call. For invoices from known vendors (templates exist), the user sees the result instantly.

Determinism: Same invoice → bit-for-bit identical output every time. No token sampling variance. Easier to audit and regression test.

Cost at volume: Templates are free. At 10K invoices/month, a 60% template hit rate saves ~$15/month at Flash-Lite pricing — negligible. At 50K+, savings compound. See the break-even table below.

⚠️ Where the hybrid creates risk

Silent template drift: Vendor changes their invoice layout, template silently extracts wrong fields, validation catches some but not all. LLM is more robust to layout changes.

Template maintenance burden: Each new vendor requires writing and testing a new template. Below ~20 active vendors, the effort often exceeds the savings.

Coverage ceiling: Long-tail vendors (infrequent, varied layouts) will always fall through to LLM anyway. The template layer only helps for the top-N vendors by volume.

Verdict: Keep the template hybrid. The speed and determinism benefits exist at any volume — they're not just about cost. The risk of silent drift is real but the existing validation layer mitigates it. The cost argument only becomes financially meaningful above ~50K docs/month with cheap models; it becomes compelling much sooner if you upgrade to GPT-5.4 or Gemini 3.1 Pro.

Better alternative? Not really — but consider prompt caching as a free complement. Your system prompt (~800 tokens, identical across all calls) qualifies for Google's and Anthropic's 90% cache discount immediately. That's an 8–12% cost reduction with zero engineering work.
